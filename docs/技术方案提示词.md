# 技术方案实施提示词

你是一名资深全栈工程师。请先阅读仓库 README 和 `docs/技术方案.md`，然后基于当前仓库实现在线考试与电子作业平台的一期 MVP。以技术方案为需求依据；若仓库已有代码或约定，先沿用现有结构。

## 技术要求

- 后端使用 Python 3.11+、FastAPI、Pydantic，提供 `/api/v1` REST API。
- 使用 PostgreSQL、SQLAlchemy 2.x 和 Alembic 迁移。
- 提供 Dockerfile、Docker Compose、健康检查与 `.env.example`；严禁提交真实密钥。
- 集成 Ollama 本地 HTTP API，通过 `OLLAMA_BASE_URL` 和 `OLLAMA_MODEL` 配置，不要在代码中写死模型名称。Ollama 可通过 Docker Compose 的 `ai` profile 启动并持久化模型数据；服务不可用时，考试、题库和阅卷核心流程仍可使用。
- 采用清晰的模块化单体结构，将模型调用封装在独立适配层。
- 白板未指定前端框架。先检查仓库现状；若无既有前端，不要擅自引入重型前端方案或假设产品视觉规范。

## MVP 功能

实现账号与组织角色基础、题库维护、考试/作业创建和发布、考生开始作答与答案保存、提交、客观题自动评分、主观题人工阅卷，以及成绩发布和基本统计。按技术方案建议建模用户/组织/成员、题目、AI 题目草稿、考试、作答记录和阅卷。

## 业务与安全规则

- 所有资源都要在服务端按用户身份、组织和角色授权；考生不能读取他人答卷或提交前的标准答案。
- 开始作答时保存题目和选项快照；答案可重复保存，最终提交应幂等并保持成绩一致。
- 客观题依明确规则评分；未明确计分规则的题型转人工复核，不要猜测。Ollama 不得裁定正式考试成绩。
- Ollama 仅根据组织者提供的主题、题型和难度生成候选题与解析；结果必须经过人工审核、修改和确认后才能进入正式题库。校验模型返回结构和字段，不向模型发送考生个人信息、答卷或成绩。
- 密码使用安全哈希；凭据从环境变量读取；对发布、提交、阅卷和成绩发布保留必要审计信息。
- 白板中央数字无法辨认，不得用作考试编号、账号或配置。`examcoo.com` 只作为公开功能范围参考，不复制其代码、品牌素材或专有界面。
