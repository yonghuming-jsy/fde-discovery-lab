# 在线考试与电子作业平台技术方案

> 状态：初稿。依据白板可辨认内容整理；具体业务规则以确认后的需求为准。

## 1. 项目定位

建设一个面向学校、培训机构及企业的在线考试与电子作业平台，支持题库维护、组卷、考试/练习发布、在线作答、阅卷和成绩查看。白板中的“考试酷”及 [examcoo.com](https://www.examcoo.com/) 作为公开功能参考，不复制其代码、品牌素材或专有界面。

考试酷公开首页列出的参考能力包括自测练习、统一考试、知识竞赛、电子作业、组卷、答卷评阅和成绩管理；系统一期聚焦可独立交付的基础闭环。

## 2. 白板中的明确约束

- 后端框架：按白板“Fast API”理解为 **FastAPI**。
- Python：**3.11+**。
- 部署：**Docker** 容器化，提供 Docker Compose 本地运行方式。
- 文档：`docs/技术方案.md` 与 `docs/技术方案提示词.md`。
- 白板中央的一串数字含义不清，不作为考试编号、账号或配置写入系统。

## 3. 一期范围

### 角色

- **组织者**：教师、培训官或 HR 管理者，可维护题目、创建考试/作业、发布和查看成绩。
- **考生**：学生或员工，可查看已分配任务、参加考试并查看已发布成绩。
- **平台管理员**：管理组织、成员和基础配置。

### 核心流程

1. 组织者创建题目并归入题库，可按题型、知识点和难度筛选。
2. 组织者创建考试或作业，设置开始/截止时间、时长、可考次数、题目顺序和成绩发布规则；支持手动选题，预留按条件随机组卷。
3. 考生进入任务后生成一次作答记录，服务端保存试卷快照和题目顺序。
4. 作答过程定期保存；提交操作幂等，超时或重复提交不会产生多份成绩。
5. 单选、多选、判断等客观题自动评分；主观题进入人工阅卷。
6. 组织者发布成绩并查看参与率、分数分布和个人答卷。

### 一期题型建议

单选、多选、判断、填空和简答。客观题规则需要明确答案、分值及多选计分方式；填空和简答在规则未确认前默认人工复核。

## 4. 技术架构

采用**模块化单体**，先保证业务闭环和可维护性，不在早期拆分微服务。

- **API 服务**：Python 3.11+、FastAPI、Pydantic；以 `/api/v1` 提供 REST API 和 OpenAPI 文档。
- **数据访问**：PostgreSQL；SQLAlchemy 2.x；Alembic 管理迁移。
- **网页端**：响应式 Web 界面；白板未指定前端框架，实施前确认后再定。
- **异步任务/缓存**：一期可不部署 Redis；定时发布、批量通知或任务量确有需要时再加入。
- **部署**：Dockerfile 与 Docker Compose；本地包含 API 和 PostgreSQL，提供健康检查和示例环境变量。

建议代码按 `api`、`schemas`、`models`、`services`、`repositories`、`core` 和 `db` 分层，避免把权限、评分和组卷规则写进路由函数。

## 5. 领域模型建议

- `User`、`Organization`、`Membership`：账号、组织及成员角色。
- `Question`、`QuestionOption`：题干、题型、选项、标准答案、解析、知识点和难度。答案字段需限制访问。
- `Exam`、`ExamQuestion`：考试/作业配置及固定题目或组卷规则。
- `Attempt`、`Answer`：考生作答、开始/提交时间、状态、答案快照及得分。
- `Review`：主观题阅卷人、评分、评语和操作时间。

分值、作答状态和成绩以服务端为准；每次考试保留题目和选项快照，避免题库后续修改影响历史答卷。

## 6. API 草案

- `POST /api/v1/auth/login`、`POST /api/v1/auth/refresh`：登录和刷新凭证。
- `GET/POST /api/v1/questions`、`GET/PATCH/DELETE /api/v1/questions/{id}`：题库维护。
- `GET/POST /api/v1/exams`、`POST /api/v1/exams/{id}/publish`：考试创建和发布。
- `POST /api/v1/exams/{id}/attempts`：开始作答并返回考生可见试卷。
- `PUT /api/v1/attempts/{id}/answers/{question_id}`：保存答案。
- `POST /api/v1/attempts/{id}/submit`：提交并触发自动评分。
- `POST /api/v1/reviews/{answer_id}`：人工阅卷。
- `GET /api/v1/exams/{id}/results`：组织者成绩与统计。

考生接口不得在提交前返回标准答案、内部评分规则或其他考生数据。所有资源查询都按组织和角色做服务端授权。

## 7. 安全与可靠性

- 密码使用 Argon2id 或同等级密码哈希；令牌设过期时间并支持撤销/刷新。
- 实施组织级 RBAC；组织者只能访问授权组织的题库、考试和成绩。
- 对发布、开始作答、提交、阅卷和成绩发布记录审计事件。
- 答案保存使用版本号或幂等键处理重复请求；正式提交使用数据库事务。
- 输入使用 Pydantic 校验；上传附件如纳入后续范围，限制类型、大小并隔离存储。
- 密钥只通过环境变量注入；仓库提交 `.env.example`，不提交真实凭据。

## 8. Docker 与本地运行

提供 `Dockerfile`、`compose.yaml`、数据库迁移和健康检查。开发者复制 `.env.example` 后启动服务；数据库初始化和迁移应有明确命令，启动失败时能从日志定位配置或迁移错误。生产环境使用独立密钥、HTTPS、备份策略和非 root 容器用户。

## 9. 交付阶段

1. **基础工程**：配置、数据库连接、迁移、健康检查和角色模型。
2. **题库**：题目 CRUD、题型校验、知识点和权限。
3. **考试作答**：考试配置、发布、作答快照、自动保存和提交。
4. **阅卷成绩**：客观题评分、主观题复核、成绩发布和基本统计。
5. **容器交付**：Docker Compose、本地启动说明、示例数据和安全配置说明。
