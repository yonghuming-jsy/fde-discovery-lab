
# 在线考试与电子作业平台技术方案

> 状态：初稿。依据白板可辨认内容整理；具体业务规则以确认后的需求为准。

## 1. 项目定位

建设一个面向学校、培训机构及企业的在线考试与电子作业平台，支持题库维护、组卷、考试/练习发布、在线作答、阅卷和成绩查看。白板中的“考试酷”及 [examcoo.com](https://www.examcoo.com/) 作为公开功能参考，不复制其代码、品牌素材或专有界面。

一期增加 Ollama 本地大模型能力，辅助组织者起草题目和解析。AI 输出只作为草稿，须由组织者审核、修改并确认后才能入题库；考试评分仍使用明确的客观题规则或人工阅卷，不由大模型裁定。

## 2. 白板中的明确约束

- 后端框架：按白板“Fast API”理解为 **FastAPI**。
- Python：**3.11+**。
- 部署：**Docker** 容器化，提供 Docker Compose 本地运行方式。
- 本地大模型：集成 **Ollama**；模型名称与服务地址可配置，不在代码中写死具体模型。
- 文档：`docs/技术方案.md` 与 `docs/技术方案提示词.md`。
- 白板中央的一串数字含义不清，不作为考试编号、账号或配置写入系统。

## 3. 一期范围

### 角色

- **组织者**：教师、培训官或 HR 管理者，可维护题目、创建考试/作业、发布和查看成绩。
- **考生**：学生或员工，可查看已分配任务、参加考试并查看已发布成绩。
- **平台管理员**：管理组织、成员和基础配置。

### 核心流程

1. 组织者创建题目并归入题库，可按题型、知识点和难度筛选。
2. 组织者可填写主题、题型、知识点和难度，让 Ollama 生成题目与解析草稿；草稿需人工审核和修改后才能保存为正式题目。
3. 组织者创建考试或作业，设置开始/截止时间、时长、可考次数、题目顺序和成绩发布规则；支持手动选题，预留按条件随机组卷。
4. 考生进入任务后生成一次作答记录，服务端保存试卷快照和题目顺序。
5. 作答过程定期保存；提交操作幂等，超时或重复提交不会产生多份成绩。
6. 单选、多选、判断等客观题按明确规则自动评分；主观题进入人工阅卷。Ollama 不参与正式评分。
7. 组织者发布成绩并查看参与率、分数分布和个人答卷。

### 一期题型建议

单选、多选、判断、填空和简答。客观题规则需要明确答案、分值及多选计分方式；填空和简答在规则未确认前默认人工复核。

## 4. 技术架构

采用**模块化单体**，先保证业务闭环和可维护性，不在早期拆分微服务。

- **API 服务**：Python 3.11+、FastAPI、Pydantic；以 `/api/v1` 提供 REST API 和 OpenAPI 文档。
- **数据访问**：PostgreSQL；SQLAlchemy 2.x；Alembic 管理迁移。
- **网页端**：响应式 Web 界面；白板未指定前端框架，实施前确认后再定。
- **Ollama 服务**：通过独立 AI 适配层调用 Ollama 的本地 HTTP API；由 `OLLAMA_BASE_URL` 和 `OLLAMA_MODEL` 配置。请求设置超时与错误处理；服务不可用时题库、考试和阅卷等核心流程仍可正常使用。
- **异步任务/缓存**：AI 生成先使用同步请求并设置合理超时；若后续生成耗时或并发量较大，再引入后台任务或 Redis。
- **部署**：Dockerfile 与 Docker Compose；API、PostgreSQL 常规启动；Ollama 可通过 `ai` profile 单独启用并持久化模型数据，避免默认启动时自动下载大型模型。Ollama 仅在本机或受控内部网络访问，不直接暴露到公网。

建议代码按 `api`、`schemas`、`models`、`services`、`repositories`、`core` 和 `db` 分层，将 Ollama 调用封装在独立适配器中，避免业务逻辑依赖具体模型供应方。

## 5. 领域模型建议

- `User`、`Organization`、`Membership`：账号、组织及成员角色。
- `Question`、`QuestionOption`：题干、题型、选项、标准答案、解析、知识点和难度。答案字段需限制访问。
- `QuestionDraft`：AI 生成的候选题干、选项和解析、生成参数、创建者及审核状态；获组织者确认后再转为正式题目。
- `Exam`、`ExamQuestion`：考试/作业配置及固定题目或组卷规则。
- `Attempt`、`Answer`：考生作答、开始/提交时间、状态、答案快照及得分。
- `Review`：主观题阅卷人、评分、评语和操作时间。

分值、作答状态和成绩以服务端为准；每次考试保留题目和选项快照，避免题库后续修改影响历史答卷。

## 6. API 草案

- `POST /api/v1/auth/login`、`POST /api/v1/auth/refresh`：登录和刷新凭证。
- `GET/POST /api/v1/questions`、`GET/PATCH/DELETE /api/v1/questions/{id}`：题库维护。
- `POST /api/v1/ai/question-drafts`：提交主题、题型、难度等参数，请求 Ollama 生成候选题目草稿。
- `POST /api/v1/question-drafts/{id}/approve`：组织者审核后将草稿保存为正式题目。
- `GET/POST /api/v1/exams`、`POST /api/v1/exams/{id}/publish`：考试创建和发布。
- `POST /api/v1/exams/{id}/attempts`：开始作答并返回考生可见试卷。
- `PUT /api/v1/attempts/{id}/answers/{question_id}`：保存答案。
- `POST /api/v1/attempts/{id}/submit`：提交并触发客观题评分。
- `POST /api/v1/reviews/{answer_id}`：人工阅卷。
- `GET /api/v1/exams/{id}/results`：组织者成绩与统计。

考生接口不得在提交前返回标准答案、内部评分规则或其他考生数据。所有资源查询都按组织和角色做服务端授权。AI 接口只接收组织者授权的生成请求，不把考生个人信息、真实作答记录或正式成绩发送给模型。

## 7. 安全与可靠性

- 密码使用 Argon2id 或同等级密码哈希；令牌设过期时间并支持撤销/刷新。
- 实施组织级 RBAC；组织者只能访问授权组织的题库、考试和成绩。
- 对发布、开始作答、提交、阅卷和成绩发布记录审计事件。
- 答案保存使用版本号或幂等键处理重复请求；正式提交使用数据库事务。
- 输入使用 Pydantic 校验；上传附件如纳入后续范围，限制类型、大小并隔离存储。
- 密钥只通过环境变量注入；仓库提交 `.env.example`，不提交真实凭据。模型服务地址和模型名可用环境变量配置。
- 把 AI 生成结果视为不可信输入，校验结构、题型和字段长度；组织者审核前不得发布或用于考试。

## 8. Docker 与本地运行

提供 `Dockerfile`、`compose.yaml`、数据库迁移和健康检查。开发者复制 `.env.example` 后启动 API 和 PostgreSQL；需要本地 AI 出题时再启用 Ollama profile，并按说明拉取所选模型。模型数据使用持久卷，避免容器重建后重复下载。数据库初始化和迁移应有明确命令，启动失败时能从日志定位配置或迁移错误。生产环境使用独立密钥、HTTPS、备份策略和非 root 容器用户；Ollama 仅部署在可信内部网络。

## 9. 交付阶段

1. **基础工程**：配置、数据库连接、迁移、健康检查和角色模型。
2. **题库与 AI 草稿**：题目 CRUD、题型校验、知识点和权限；接入 Ollama 草稿生成、人工审核及降级处理。
3. **考试作答**：考试配置、发布、作答快照、自动保存和提交。
4. **阅卷成绩**：客观题评分、主观题复核、成绩发布和基本统计。
5. **容器交付**：Docker Compose、可选 Ollama profile、本地启动说明、示例数据和安全配置说明。
