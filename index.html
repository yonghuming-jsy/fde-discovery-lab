01

MVP 边界：先交付可验证的知识闭环

SCOPE & OUTCOME

一期的目标不是堆齐所有 AI 能力，而是证明：用户能在授权范围内导入资料、检索、获得带来源的回答，并让管理员审核 Wiki 更新。

01 / ACCESS

账号与租户

建立租户、成员、组织单元和角色；API 对资源做服务端授权。

02 / INGEST

资料导入

接收 Markdown 和 UTF-8 文本，分块并建立可检索索引。

03 / ANSWER

RAG 问答

按权限检索片段，生成回答并展示文档与片段引用。

04 / GOVERN

Wiki 草稿

抽取实体和关系，保留来源；审核通过后再发布。

一期纳入

交付物

  • 平台、租户与组织单元管理
  • 角色和知识库范围校验
  • 文本导入、分块、向量化与检索
  • 带引用的问答与 Wiki 草稿审核
  • Harness 统一日志、校验与审计事件
需单独评估

当前未承诺

  • PDF、Word、Excel 等 Office 文件解析
  • 跨租户搜索、公开匿名问答
  • 外部 SaaS 模型与私有化 GPU 的正式 SLA
  • 海量向量检索优化、复杂知识图谱编辑器
  • 生产级备份、灾备、计费与多区域部署

建议的交付节奏

W1 · ALIGN

补齐业务量、租户数、数据权限和验收问题。

W2 · BUILD

打通租户、组织树、导入和授权边界。

W3 · RAG

完成检索、引用、拒答和质量评估样例。

W4 · PILOT

小范围试用，按验收结果决定扩展项。

验收原则每项功能都要能用一个可重复的场景验证：给定租户、用户、资料与问题，系统返回符合权限的内容和可核对来源。

03

多租户权限：先限定数据，再判断角色

TENANT ISOLATION

租户隔离不是界面筛选条件，而是所有数据库查询和业务 API 的强制约束。任何请求都应从已验证身份推导租户范围，不信任客户端传来的 tenant_id。

角色管理范围默认知识读取范围典型操作
平台管理员平台级租户默认不读取租户文档正文创建租户、首位租户管理员
租户管理员单一租户本租户授权知识库管理成员、组织树、知识库
组织单元管理员自身组织单元及后代本范围内获授权知识库管理范围内成员与资料
普通成员个人操作租户共享或所属单元明确授权的资料提问、阅读已发布 Wiki

查询前检查

  1. 验证登录态并解析用户 ID
  2. 从服务端载入成员所属租户与组织单元
  3. 先加 tenant_id 条件，再加资源授权条件
  4. 检查目标知识库范围和操作角色
  5. 记录允许或拒绝的审计事件

必须覆盖的拒绝用例

  • 用户修改请求参数读取其他租户文档
  • 单元管理员访问兄弟单元资料
  • 平台管理员尝试默认读取租户正文
  • 成员调用文档导入或 Wiki 发布接口
  • 已撤销权限的旧会话继续访问私有资料

可提问并查看已发布 Wiki；只能检索租户共享或所属单元已授权的知识库。

04

RAG 成本：把每次回答拆成可计量的调用

RETRIEVAL & TOKENS

RAG 的月成本不只取决于聊天模型单价。分块与 Embedding 产生索引成本；每次问题可能包含重写、检索、重排、回答或重试，多步调用要乘进预算。

01 · INGEST

文本清洗、按规则切块并保留来源元数据。

02 · EMBED

为每个片段生成向量，记录模型与版本。

03 · RETRIEVE

在权限过滤之后取回相关片段。

04 · GENERATE

组织上下文，生成回答并绑定引用。

月模型费 ≈ 日请求量 × 30 × 每次调用步数 × 重试系数 × 单次 Token 成本
单次 Token 成本 = (输入 Token × 输入单价 + 输出 Token × 输出单价) ÷ 1,000,000。

06

AI Harness：让每个回答经过同一组检查

POLICY & OBSERVABILITY

Harness 是服务内部的统一编排层，不假定某个特定外部产品。它接收已授权上下文，执行 RAG 流程并产生可追踪的结果。

1 · CONTEXT

用户、租户、组织单元、可用知识库 ID。

2 · RETRIEVE

先加权限过滤，再召回与问题相关的片段。

3 · GENERATE

调用模型，要求答案仅依据给定资料。

4 · VERIFY

校验引用、记录耗时、状态和审计事件。

输入约束

对用户输入、检索片段和模型输出分别处理，不让资料中的文字改写系统权限规则。

引用校验

回答中的来源 ID 必须对应本次检索结果；没有足够证据时返回不确定说明。

质量信号

跟踪召回命中、引用覆盖、拒答、延迟、错误率和人工反馈，为后续调优留下依据。

audit_event = { tenant_id, actor_id, action, resource_id, decision, trace_id, created_at }
日志只记录必要的诊断字段；敏感正文是否留存应由数据保留策略决定。
失败时的行为权限不足就拒绝；检索为空就说明资料不足；模型超时就返回可理解的失败提示。不要用没有来源的“看起来合理”答案掩盖错误。
